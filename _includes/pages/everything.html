{%- comment -%} The dense index, on its own page — decided over inlining it into the other pages, see `.agents/context/decisions.md`. Ordering: Liquid has no way to sort one list built out of two differently shaped ones, so each entry contributes a `"||"` string, the strings are sorted as text (which is why the dates are zero-padded and written biggest unit first), and the loop dereferences each one back to its source. Nothing is copied into a second data file; `_data/research.yml` and `_data/projects.yml` stay the only place these entries exist. The filter is radio inputs plus `:has()`, no JavaScript: "all" is checked in the HTML, so the page's default and its no-script state are the same complete list. The per-filter counts are all rendered at build time and CSS shows the one that matches, so the number is right without a script to recompute it. Writing has no entries yet. It keeps its filter and says so when selected, rather than being hidden until it exists. There is no talks filter: unlike writing, no talks are planned anywhere, so it would be a promise rather than a placeholder. {%- endcomment -%} {%- assign papers = site.data.research.papers -%} {%- assign projects = site.data.projects.items | where: "featured", true -%} {%- assign kinds = site.data.ui.everything.kinds -%} {%- assign rows = "" -%} {%- for p in papers -%} {%- assign k = p.date | default: "0000-00-00" -%} {%- assign rows = rows | append: k | append: "|paper|" | append: forloop.index0 | append: "," -%} {%- endfor -%} {%- for p in projects -%} {%- assign k = p.date | default: "0000-00" | append: "-00" -%} {%- assign rows = rows | append: k | append: "|project|" | append: forloop.index0 | append: "," -%} {%- endfor -%} {%- assign rows = rows | split: "," | sort | reverse -%} {%- assign n_all = rows | size -%} {%- assign n_paper = papers | size -%} {%- assign n_project = projects | size -%} {% include page-head.html title=site.data.ui.sections.everything lede=site.data.ui.everything.lede %}
